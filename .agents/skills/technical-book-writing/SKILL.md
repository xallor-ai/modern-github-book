# 技术书籍分阶段写作

把读者从已有能力带到可解释、可操作、可迁移的结果。以连续讲解单元和样章推进书稿，不把目录一次展开成整本正文，也不把验证清单当成教学。

## 接任务先判断阶段

读项目约定、当前大纲、本次相关章节及相邻衔接。只加载与任务有关的资料，不默认把全库和全部评审装进每次上下文。

区分当前事实：已有大纲、已选案例、已查资料、局部初稿、技术实测、模拟读者审查、真实读者走读、编辑定稿。文件存在不等于对应阶段通过。

| 用户请求 | 本次应完成的工作 |
| --- | --- |
| 设计/评审全书 | 固定读者、能力终点、部分与章节职责、依赖、案例演进和学习成果，区分开写条件与出版条件 |
| 开始/继续正文 | 找到已授权的下一单元，补其必要资料与案例后直接写正文，不能只返回新一轮计划 |
| 修改某节或某章 | 读取上下文，修复具体解释断层并核对相邻接口；不自动重构全书 |
| 审稿 | 给出位置、读者影响、依据和最小修法；技术、教学、编辑分别下结论 |
| 小范围文字修正 | 直接完成，不启动全书流程或增加管理材料 |

读者与范围已有明确决定时沿用。只有会改变产物的缺失信息才询问；不因流程存在而重复索要批准。用户要求整书时，内部拆成可管理的单元连续推进；不以单次上下文容量承诺整书一次定稿。

## 从大纲走到正文

### 1. 先确定当前章的教学输入

确认入章能力、学完能做什么、要讲到什么深度，找到前章实际提供的文件或例子。将尚未选定的产品、接口或环境限制局部化，不能因选读环境未就绪冻结无关基础章。

起草该章前准备一份短工作说明：中心问题、连续案例、必要资料、解释顺序、配图和练习、前后章交接。复用已有计划和记录；没有实际复用价值时不新建模板文件。详细做法见 [讲解单元与上下文](references/writing-unit.md)。

案例必须有可说明的输入、变化和结果。需要运行的内容先弄清文件树、命令、初始数据和版本；阶段快照真实存在后才链接。不要把已配置复杂门禁的后期实验环境当作零基础章节的默认起点，也不要为复现旧章节拆掉现有保护。

### 2. 查资料，并组织解释

对当前单元的关键机制查一手资料或可验证源码；变化快的产品入口、语法、权限按当前环境核对。资料记录对应论点、适用条件、来源与未知项，不按来源逐篇拼摘要。 具体版本和产品入口应来自已提供的核验材料或允许的查证；缺依据且无法查证时，先写有依据的讲解，将待核验配置明确标为草稿或占位，不凭记忆选一个版本让读者照抄。能复用的可靠解释或示例可以引用或改编，核对许可和出处；不为原创率从零发明，不用外链外包主例必要知识。

安排学习顺序：读者的问题 → 必要模型 → 小例子的因果推演 → 扩展或反例 → 迁移判断。顺序可交替，不强制每节都有相同标题、三个错误或固定字数。

### 3. 一次完成一个连续讲解单元

用“一个读者问题及其解释闭环”界定任务，通常为一节或紧密相连的数节。过小会割裂推理，过大会丢失前置与证据。输入包括本章目标、前后文、已出现术语、案例当前状态及必要来源；交付正文、关联图文/代码与工作记录中的验证边界。

正文要解释输入是什么、哪一步改变什么、为何如此、读者能观察什么、改一个条件会怎样。不能先贴复杂最终配置再要求核对；逐步引入新概念，必要时给最终整合例子。已讲过的知识简短回指，新知识不能藏在附件脚本里。

分支、路径和权限只在理解或操作确实依赖时交代。不把作者状态契约、成果编号、审查待办或实验回执变成正文。代码与日志优先提供可复制文本，截图补空间定位与可见状态，原理用示意图与文字解释。

### 4. 完成单元后整合章节

先自查因果和可操作性，再检查术语、参数、示例文件、引用和前后衔接。保留真实限制；无法运行的部分可以写原理和待核验草稿，不能编造成功结果。必要配图要有采集条件，来源与实际画面对应；历史运行不保证能补拍当时状态。

单元拼接后必须从章首连续读到章末，消除重复引言、互相推诿的前置、矛盾的数据状态和风格断裂。并行作者只承担依赖清楚、文件归属明确的任务，并由整合者维护同一案例与术语；不要将20章直接发给20个Agent后按编号拼接。

### 5. 连续样章通过后再扩大

选能检验入门坡度与机制解释的连续章节，分别做技术核验、读者走读和编辑审稿。AI模拟读者有助于找跳步，但不替代目标读者真正使用正文。未完成真实走读要单列，不称已经验证读者学会。

独立审查在用户要求或复杂度确有必要时进行；模型审稿不是出版机构认可，多模型意见不以多数票决定。逐条核验发现，保留采纳、局部修复或不采纳的理由，复审只针对实质修复和新增风险，不循环索取更好看的结论。

门槛和后期工序见 [审稿与交付](references/review-and-delivery.md)。正文之外仍要做全书连续编辑、图文渲染、索引导航、版本与版权检查；样章通过不等于全书出版定稿。

## 工作范围与证据

- 篇幅仅供识别解释不足、过载与工作量；不能为凑字数重复规则，也不能为压字数删必要机制。
- 工作记录只保留续写、复核和维护需要的信息，既有资料有权威入口就回指，不重复保存多套目录或政策。
- Skill本身不授予建仓、改权限、发评论、部署、提交、推送或合并的权限；遵循用户授权和仓库约定。
- 临时实验不污染正文或共享环境；只读核验、静态检查、实际运行、读者理解分别描述。
- 完成说明写清本轮产物、实际验证、未完成的本地/云端/读者步骤和下一可执行单元，不能把计划描述为实施成果。
